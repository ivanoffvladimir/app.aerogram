# CLAUDE.md — инструкция для ИИ-агентов

Читается в начале каждой сессии. Устаревший файл хуже отсутствующего: если правило
здесь разошлось с кодом — сначала чиним файл, потом пишем код.

## 1. Что это за проект

**Logistics OS** — независимая B2B-платформа управления доставкой через нескольких
перевозчиков. Подключается к существующим договорам клиента, нормализует расчёт,
оформление и трекинг, и рекомендует вариант с лучшим ожидаемым бизнес-результатом.

Центральная функция — **Decision Engine**:
`Connect → Compare → Decide → Ship → Track → Control → Settle → Learn`.

Это не биржа грузов и не ещё один классический TMS. Ценность в том, что каждое
решение сохраняется неизменяемым снимком и превращается в обучающий датасет:
рекомендация → выбор → override → фактический результат доставки.

**Действующее ТЗ — v3, `docs/tz/v3/`.** Контракт API — `docs/tz/v3/openapi.yaml`;
расхождение кода с ним есть ошибка кода. Решения — `docs/adr/`.

Пилот: 6 перевозчиков (Major Express, СДЭК, ПЭК, Деловые Линии, Почта России,
Яндекс Доставка), 3–5 корпоративных клиентов, 10 000+ отправлений для первичной
аналитики. Почта России добавлена шестой решением ADR-0020; порядок постройки
адаптеров там же.

> ТЗ v1 (`docs/tz/archive-v1/`) — архив. По нему написаны недели 1–5 и он объясняет,
> каким требованиям отвечает старый код. Новый код по нему писать нельзя.
>
> **Нумерация `FR-x.y` — из архива.** В v3 её нет ни одной: там разделы прозой.
> Ссылки вида `FR-3.6` в коде читаются как история и переписывания не требуют,
> но планировать по ним новую работу нельзя: требование может существовать
> только в v1. Прежде чем брать пункт, найдите его в v3 по смыслу.

## 4. Правила зависимостей (проверяются import-linter в CI)

Слои внутри модуля, сверху вниз — зависимости только вниз:

```
router  →  service  →  repository  →  models
                ↓
             shared
```

Межмодульные правила:

1. `carriers` **не знает** ни об одном модуле домена. Адаптер принимает DTO
   и возвращает DTO, к базе не обращается (ADR-0005) и ничего не «синхронизирует»:
   он отдаёт данные, а пишет их домен (ADR-0009).
2. Домен обращается к перевозчикам **только** через `carriers.registry` и DTO
   из `carriers.base`, никогда напрямую к `carriers.cdek`, `carriers.major` и т. п.
3. `routing` не вызывает адаптеры: он работает на уже полученных `RateOffer`.
   Порядок вызовов — `rating` считает, `routing` ранжирует (ADR-0014).
4. `intelligence` и `billing` работают **только на чтение** домена и не вызывают
   адаптеры.
5. `shared` не зависит ни от чего внутри проекта.
6. Любой доступ к БД — через `repository.py` модуля. SQL вне репозиториев запрещён.

Контракты: `.importlinter`. Красный import-linter — блокирующая ошибка CI.

## 6. Соглашения по коду

**Типизация.** `mypy --strict` для `shared/`, `carriers/`, `rating/`, `routing/`,
`shipments/`. `Any` не появляется в диффе. Публичные функции аннотированы полностью.

**Деньги.** Целое число минорных единиц (`BIGINT amount_minor`) плюс код валюты
(`CHAR(3)`), тип `shared.money.Money`. `float` для денег — ошибка ревью,
арифметика в минорных единицах, деление — только через явное правило округления
(ADR-0011). Сумма без валюты не существует: складывать разные валюты запрещено.

**Время.** Только timezone-aware UTC (`shared.clock.utcnow`), в БД `TIMESTAMPTZ`.
Отображение — по таймзоне тенанта, на фронте. `datetime.now()` без tz запрещён.

**Идентификаторы.** Первичные ключи — UUIDv7 (`shared.ids.uuid7`), сортируемы по времени.

**Ошибки.** Иерархия `shared.errors.AerogramError`. Ошибка перевозчика **никогда** не
даёт `500`: сбой одного перевозчика не ломает расчёт остальных, он становится
элементом `failures` в ответе. Формат ответа API единый:
`{"error": {"code", "message", "field", "carrier_code", "request_id"}}`.

**Внешние вызовы.** Всегда таймаут (connect + read), ретраи через tenacity,
circuit breaker, `correlation_id` и метрики. Клиент без явного таймаута — ошибка ревью.

**Идемпотентность.** `Idempotency-Key` обязателен на `POST /v1/decisions`
и `POST /v1/shipments`. Тот же ключ и то же тело — тот же результат; тот же ключ
и другое тело — `409`. Вызов создания у перевозчика имеет внутренний `operation_id`
и retry-safe состояние; при таймауте после отправки запроса адаптер сверяется
с перевозчиком до повтора.

**Неизменяемость.** Снимки `RateOffer`, `Recommendation` и `Decision` после принятия
решения не пересчитываются и не правятся задним числом — на них строится аналитика.

**Тенанты.** Каждая бизнес-таблица содержит `tenant_id` и политику RLS.
Транзакция начинается с `SET LOCAL app.tenant_id`. Приложение подключается к БД
ролью **без** `BYPASSRLS`. Доступ к чужому объекту по прямому идентификатору
даёт `404`, а не `403`.

**JSONB** — только для неизменяемых снимков, условий и действий правил и расширений
перевозчика. Всё, по чему фильтруем, живёт в колонках.

**Персональные данные.** ФИО, телефоны, адреса не попадают в логи и трассировки —
маскирование через `shared.logging.mask_pd`. Учётные данные перевозчиков
не попадают в ответ, лог и снимок никогда. Сырые ответы ТК хранятся 30 суток.

**Язык.** Интерфейс, письма, тексты ошибок — русский. Код, имена, коммиты — английский.

## 7. Что нельзя делать без построчного ревью человека

Здесь ошибка стоит дороже всего и обнаруживается позже всего:

1. Схема БД и миграции.
2. RLS и всё, что касается изоляции тенантов.
3. Контракт `CarrierAdapter` (`carriers/base.py`).
4. Идемпотентность и сверка «призраков».
5. Работа с деньгами: округления, минорные единицы, валюта.
6. Аутентификация, права, хранение секретов.
7. Обработка персональных данных.
8. Формула рекомендации и её версионирование (`algorithm_version`, `policy_version`).

По каждому пункту решение принимает человек и фиксирует в ADR; агент реализует уже
принятое решение.

## 8. Гигиена

- Агент не «улучшает» код вне поставленной задачи. Любая правка за пределами задачи —
  отдельный PR.
- Агент **не правит фикстуры и не ослабляет ассерты**, чтобы тест позеленел.
  Красный тест — сигнал, а не препятствие.
- Агент не меняет миграции, уже применённые в staging или prod. Только новая миграция.
- Тесты пишутся вместе с кодом, в той же задаче. Отложенные тесты не пишутся никогда.
- Ветка на задачу, PR с описанием, зелёный CI до слияния.
- Каждое архитектурное решение — короткий ADR в `docs/adr/`.
