# Major Express — что осталось до рабочего адаптера

Сейчас в проекте **заглушка**: `backend/src/aerogram/carriers/major/`.
Она реализует контракт `CarrierAdapter` целиком и на любой вызов отвечает
`carrier_not_configured` с указанием причины — не заполнены доступы или
не добавлено описание веб-сервиса. В реестре адаптеров она **не
зарегистрирована**: зарегистрированный адаптер попадает в каждый расчёт
тенанта и добавлял бы в выдачу строку отказа при каждом обращении.

Проверить, что видит оператор сейчас:

```bash
cd backend
uv run python -c "
import asyncio
from aerogram.carriers.base import CarrierAccount
from aerogram.carriers.major import MajorExpressAdapter
acc = CarrierAccount(account_id='1', carrier_code='major',
                     mode='own_contract', credentials={'login': 'x'})
try: asyncio.run(MajorExpressAdapter().quote(None, acc))
except Exception as e: print(e)
"
```

## Шаги подключения

### 1. Доступы к веб-сервису — есть у заказчика

Логин и пароль Basic Auth. Заводятся по инструкции
[«Доступы перевозчиков»](carrier-credentials.md):

```bash
uv run python scripts/set_carrier_credentials.py --tenant <uuid> --carrier major
```

В репозиторий, в `.env` и в переписку они не попадают.

### 2. WSDL — нужен от перевозчика

Файл кладётся в `backend/src/aerogram/carriers/major/wsdl/` и версионируется
вместе с кодом; по сети в рантайме он не загружается (ADR-0013). Подробности
и требования к файлу — `wsdl/README.md` в том же каталоге.

Без этого шага дальше двигаться нельзя: писать SOAP-клиент по угаданной схеме
значит выдумать контракт внешней системы.

### 3. Адрес сервиса — только если отличается от указанного в WSDL

```
MAJOR_EXPRESS_ENDPOINT_URL=
```

Пусто — берётся адрес из самого WSDL. Заполняется, например, ради отдельного
тестового контура.

### 4. Зависимость `zeep` — после появления WSDL

Решение принято в ADR-0013, но в зависимости пока не добавлено: пакет без
единого потребителя только шумел бы в `pip-audit` и в отчёте по лицензиям.
Добавляется тем же коммитом, что и первый настоящий вызов.

### 5. Реализация методов

Порядок важен: `find_by_number` обязан появиться **раньше**, чем `create`
уйдёт в бой. Без него потерянный ответ на создание оставит у перевозчика
заказ, о котором мы не знаем, — «призрак» (FR-2.5).

| Метод | Сервис Major Express |
|---|---|
| `quote` | `Calculator1` — расчёт с учётом договора клиента |
| `create` | `CreateWaybill` |
| `find_by_number` | поиск заказа по нашему номеру — сверка «призраков» |
| `track` | методы истории событий |
| `cancel` | отмена, если поддерживается договором |
| `fetch_refs` | справочники городов |

`RequestID` (GUID) сохраняется для идемпотентности и корреляции — так требует
матрица адаптеров ТЗ v3.

### 6. Сверка возможностей

`capabilities` в `adapter.py` заполнены по матрице адаптеров, а не по факту
реализации. При подключении их нужно сверить с WSDL и поправить: кабинет
показывает клиенту, чего от перевозчика ждать.

### 7. Регистрация

Последним шагом адаптер регистрируется в реестре — до этого момента он
не участвует в расчётах.
