# Что на самом деле делает catapulto.ru в «массовых отправлениях»

Разбор публичных страниц 4 сентября 2026 года, после того как домен открыли
в сетевой политике окружения. Источник — сайт и база знаний catapulto.ru,
раздел «Помощь»: страницы «Массовые отправления» и «Расчеты для массовых
отправлений».

## Главное: рассылки писем у них нет

Поиск по публичным страницам (главная, «Бизнесу», «Частным лицам», «Службы
доставки», «Частые вопросы», база знаний из 47 статей) даёт **ноль**
упоминаний слов «рассылка», «письмо», «заказное», «Почта России».

Catapulto — **агрегатор курьерских служб**: «программное обеспечение,
объединяющее различные курьерские службы в одном месте», расчёт «в 15
службах», поиск лучших условий «по цене, скорости, отзывам и рейтингу».
То есть по существу это тот же продукт, что и наш: rate shopping плюс
оформление.

Массовая рассылка писем Почтой России — **другая задача**, и на публичной
части их сайта её нет. Если она существует, то только внутри кабинета,
за входом.

## Что у них называется «массовыми отправлениями»

Не рассылка писем, а **пакетная работа с получателями**: один отправитель,
много получателей, расчёт и оформление списком.

Порядок, по их же инструкции:

1. **Раздел «Отправления» → вкладка «Массовые отправления».** Внутри два
   списка: «Расчёты» — сохранённые черновики, «Отправления» — те расчёты,
   по которым отправления уже созданы.
2. **Выбор адреса отправителя** — контакт из адресной книги или новый.
3. **Получатели, четыре способа:** добавить вручную, импорт, сохранённые
   списки и «файл поиска» — шаблон со столбцами, по которому система
   находит совпадения **в собственной адресной книге клиента** и собирает
   из них список.
4. **Груз:** «Применить для всех получателей» либо «Добавить индивидуально
   для каждого». Массовое редактирование — по чекбоксам в списке.
5. **Список уходит на расчёт.**
6. **Выбор приоритета — цена или скорость;** система подбирает лучший
   вариант **для каждого получателя отдельно**. Есть «конструктор тарифов»:
   выбрать предпочитаемую службу, а любой подобранный вариант заменить
   персонально по конкретному получателю.
7. Создание отправлений и вызов курьера.

Мелочь, которая говорит о зрелости продукта: название массового расчёта
задаётся шаблонно по текущей дате и правится вручную.

## Что из этого у нас уже есть

| Шаг catapulto | У нас |
|---|---|
| Адресная книга отправителя и получателей | `directories`, экран контрагентов — **есть** |
| Расчёт по каждому получателю | `rating` — **есть** |
| Приоритет «цена или скорость» | `routing`, стратегии — **есть** |
| Персональная замена тарифа | `routing`, override с причиной — **есть** |
| Создание отправлений | `shipments` — **есть** |
| «Любимая служба» | Carrier Score и правила маршрутизации — **есть частично** |
| **Сущность «массовый расчёт»-черновик** | **нет** |
| **Импорт списка получателей и «файл поиска»** | **нет** |
| **Один груз на многих / правка по чекбоксам** | **нет** |
| **Экран реестра с построчным результатом** | **нет** |

То есть у них это **надстройка над той же машиной, что уже написана у нас**,
а не отдельный продукт. Недостающее — пакетная обёртка: черновик расчёта,
импорт списка, применение груза ко многим и экран реестра.

## Почему это важно для ADR-0021

ADR-0021 писался под задачу «массовая рассылка писем Почтой России» и оценил
её как второй продукт — с партиями, Ф.103, сдачей в ОПС и пакетным трекингом.
Эта оценка остаётся верной **для рассылки писем**.

Но продукт, названный образцом, делает не это. «Как у catapulto» — это
пакетный слой над Decision Engine, и он **существенно дешевле**: новых
таблиц немного, внешних контрактов нет вовсе, вся логика уже написана
и покрыта тестами.

Это две разные работы, и выбирать между ними должен человек.
