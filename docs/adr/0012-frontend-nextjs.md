# ADR-0012. Фронтенд на Next.js

**Статус:** принято
**Дата:** 30 августа 2026
**Заменяет:** ADR-0007 (React Router 7). Каркас на Vite + Ant Design удаляется.

## Контекст

Раздел 1 фронт-ТЗ v3 задаёт baseline: Next.js, TypeScript strict, TanStack Query,
React Hook Form со схемной валидацией, типизированный клиент, сгенерированный
из OpenAPI, Playwright для E2E. Ant Design в ТЗ не упомянут вовсе.

Существующий фронт — каркас на 519 строк: Vite, React 18, Ant Design, React Router 7,
Zustand. Реально работают три экрана: вход, дашборд, пустой список отправлений.

## Решение

Переходим на Next.js по ТЗ. Каркас на Vite удаляется целиком, а не переносится
по частям. TanStack Query сохраняется — он есть и в ТЗ. Zustand уходит: server
state держит TanStack Query, а форм-состояние — React Hook Form, и третье
хранилище состояния между ними не нужно.

## Обоснование

Терять 519 строк каркаса дешевле, чем расходиться с ТЗ по стеку фронта на весь
проект. Из этих строк ценность имеют разве что тексты на русском и разметка формы
входа, и они переносятся вручную за час.

Ключевое требование, ради которого стоит следовать ТЗ буквально: клиент API
генерируется из `docs/tz/v3/openapi.yaml`. Это делает расхождение бэкенда
и фронта ошибкой сборки, а не находкой на демонстрации.

Ant Design не запрещён, но и не требуется. Решение по библиотеке компонентов
принимается отдельно при написании первых экранов; до тех пор её нет.

## Последствия

* `frontend/` пересоздаётся; Dockerfile фронта и `make front` переписываются.
* Добавляется генерация клиента из OpenAPI и проверка её актуальности в CI.
* Playwright заменяет vitest в роли E2E; модульные тесты остаются на vitest.
* Server-side rendering в MVP не используется как продуктовая возможность:
  кабинет за авторизацией. Next.js берётся ради контракта и инструментов,
  и это осознанно, а не как задел под SSR.
