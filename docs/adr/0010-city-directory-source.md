# ADR-0010. Справочник городов наполняется подсказками ДаData, а не своей копией ФИАС

**Статус:** принято для MVP-0; лицензия стартового датасета остаётся вопросом к человеку
**Дата:** 30 августа 2026

## Контекст

`cities` — единый ключ адресации между перевозчиками (FR-8.1): в нём живёт
`city_fias_id`, на который ссылаются адресная книга, `city_carrier_map`
и терминалы. Наполнять таблицу можно тремя способами:

| Источник | Что даёт | Чего стоит |
|---|---|---|
| `github.com/hflabs/city` (1117 городов) | Ровно те поля, что у модели `City`, включая население и координаты | CC-BY-SA 4.0: указание авторства и share-alike на производную базу — вопрос к юристу |
| `github.com/hflabs/settlement-fias-guid` (160 тыс. пунктов) | Полнота до посёлка | Лицензия прямо запрещает коммерческое применение — не рассматривается |
| Выгрузка ГАР/ФИАС с сайта ФНС | Первоисточник, свободные условия | Десятки гигабайт и своя загрузка с обновлением |

Четвёртый способ — не держать копию вовсе и наполнять таблицу по факту
обращения из ответов ДаData.

### Как ту же задачу решает ближайший аналог

Catapulto — агрегатор примерно двадцати служб доставки, то есть тот же класс
системы, что и наш.

* До 2020 года у них были **самописные подсказки на выгрузке ФИАС**. От них
  отказались по эксплуатационной причине: ФИАС меняется в среднем дважды
  в неделю, поддерживать копию в актуальном состоянии не удавалось, качество
  подсказок падало.
* Сейчас адреса и города берутся из **«Подсказок» ДаData**; в их модуле для
  InSales магазин подключает собственный ключ dadata.ru.
* Разобранный ответ ДаData — компоненты, почтовый индекс, координаты —
  используется, чтобы удовлетворить требования API каждой ТК: СДЭК считает
  тариф по почтовому индексу, Pony Express принимает «город» и «улица, дом»
  раздельно, Dostavista — одной строкой, Яндекс Доставка отдаёт цену и
  принимает заказ только вместе с координатами.

Проверить это в первоисточнике из рабочего окружения не удалось: `catapulto.ru`
и `dadata.ru` закрыты сетевой политикой (403 на CONNECT). Сведения собраны из
поисковой выдачи по двум кейсам в блоге ДаData, ссылки — в конце.

## Решение

1. **Стартовый датасет в поставку не входит.** `cities` наполняется лениво:
   каждый ответ подсказки и стандартизации, из которого удалось вычислить ключ
   города, пишется через `CityRepository.upsert` (реализовано в неделе 3).
2. **Ключ — `fias_id`**, вычисленный лестницей `settlement → city → area →
   region`, а не полем `data.fias_id`, которое в стандартизации полного адреса
   означает дом.
3. **Сопоставление с кодами перевозчиков остаётся нашей таблицей**
   (`city_carrier_map`) с очередью ручного разбора (FR-12.3), а не выводится
   на лету из компонентов адреса.
4. **Координаты дома в `cities` не попадают.** Стандартизация возвращает
   координаты найденного объекта, то есть дома получателя; `cities` — общая
   для всех тенантов таблица без RLS (12.1, 12.7 ТЗ). Координаты возвращаются
   вызывающему в ответе нормализации и сохраняются в `addresses`, где RLS есть.

## Обоснование

**Почему не своя копия ФИАС.** Ровно та причина, по которой от неё отказался
аналог: частота обновлений первоисточника выше, чем частота, с которой мы
готовы обновлять копию, а устаревший справочник хуже отсутствующего — он
уверенно отдаёт неверный ключ. Выгрузка ГАР добавляет к этому недели работы
и десятки гигабайт ради данных, которые в MVP-0 нужны для одного перевозчика.

**Почему не `hflabs/city` сейчас.** Состав полей подходит идеально, но
CC-BY-SA 4.0 с условием share-alike на производную базу — вопрос к юристу,
а не к разработчику. Продукт работает без датасета, поэтому решение можно
принимать спокойно, а не под релиз.

**Почему таблица сопоставления, а не вывод на лету.** ТЗ называет
сопоставление городов источником большинства ошибок в мультиперевозочных
системах (раздел 5.1). Вывод «на лету» из компонентов адреса прячет ошибку
внутрь запроса: неверно сопоставленный город виден только по отказу
перевозчика. Явная таблица с признаком отката на родителя и очередью ручного
разбора делает ту же ошибку видимой и чинимой точечно — один раз для всех
последующих отправлений.

## Последствия

* Зависимость от доступности ДаData закрыта управляемой деградацией: при
  ошибке внешнего сервиса подсказки собираются из локального справочника
  и помечаются `degraded`.
* `City.population` и `City.lat`/`City.lon` остаются пустыми — их даёт только
  стартовый датасет. Следствие: ранжирование локальных подсказок по населению
  (`directories/repository.py`) фактически вырождается в алфавитный порядок
  после префиксного совпадения. Это цена варианта, а не дефект.
* Первое обращение к незнакомому городу требует доступности ДаData. Пока
  тенант работает по своей географии, второе и последующие обращения уже
  обслуживаются локально.
* Пересмотр решения — когда суточный лимит ДаData станет узким местом или
  юрист снимет вопрос по CC-BY-SA. Обратной миграции не потребуется:
  `upsert` не затирает известные поля пустыми, поэтому датасет можно залить
  поверх лениво накопленных строк.
