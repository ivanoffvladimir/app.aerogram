# ADR-0007. Переход на React Router 7

**Статус:** принято
**Дата:** 29 августа 2026

## Контекст

`pnpm audit` на ветке MVP-0 сообщил о двух уязвимостях уровня moderate
в `react-router`, попадающем в сборку через `react-router-dom` 6.x:

* открытый редирект через обратный слэш в `<Link>` и `useNavigate`
  (обход исправления CVE-2025-68470);
* инъекция произвольного конструктора в `deserializeErrors()` при гидрации SSR.

Обе относятся к ветке 6.x целиком: `6.30.6` — последняя версия шестой мажорной
линии, и исправления в неё не бэкпортированы. Единственный путь — мажорный
переход на 7.x.

Формально проверка CI не была красной: блокирующий порог задан как
`--audit-level=high`, а обе находки — moderate. То есть решение принималось
не под давлением упавшей сборки.

## Решение

Обновить `react-router-dom` с `^6.28.0` до `^7.18.3`. Импорты остаются
из пакета `react-router-dom`.

## Обоснование

Вторая уязвимость нас не касается: SSR в продукте нет, кабинет — SPA,
`deserializeErrors()` не выполняется. Первая касается прямо: открытый редирект
в `<Link>` и `useNavigate` работает в SPA, а кабинет — точка входа
авторизованного пользователя, где переход на подставленный внешний адрес
превращается в правдоподобный фишинг с сохранённой сессией.

Цена перехода в текущем состоянии кода минимальна: React Router используется
в четырёх файлах (`main.tsx`, `App.tsx`, `LoginPage.tsx`, `AppLayout.tsx`)
и только базовыми примитивами — `BrowserRouter`, `Routes`, `Route`, `Navigate`,
`Outlet`, `useNavigate`, `useLocation`. Все они присутствуют в 7.x с той же
семантикой, изменений в коде не потребовалось вообще.

Это и есть причина делать переход сейчас, а не потом: через месяц маршрутизация
обрастёт загрузчиками данных и защищёнными маршрутами, и тот же переход станет
многодневной задачей.

**Импорты оставлены из `react-router-dom`, а не переведены на `react-router`.**
В 7.x рекомендуется импортировать из `react-router`, но pnpm использует строгую
раскладку `node_modules`: `react-router` доступен только как транзитивная
зависимость и прямой импорт из него сломался бы. Объявлять его второй прямой
зависимостью ради стилистики импортов — лишняя точка рассинхронизации версий.

**Порог `--audit-level=high` в CI оставлен прежним.** Сейчас проект чист и на
уровне moderate, но опускать порог значит останавливать любую задачу из-за
свежей moderate-находки в транзитивной зависимости фронта. Такие находки
разбираются решением человека, как эта, а не блокировкой чужой работы.

## Последствия

* `pnpm audit` проходит на уровне `moderate` без находок.
* Переход на загрузчики данных и `createBrowserRouter` из 7.x возможен позже,
  но обязательным не становится: текущая декларативная схема маршрутов
  поддерживается.
* React 18.3.1 удовлетворяет требованиям 7.x, обновление React не потребовалось.
